# 第九章：综合串联题（高频）

> **学习位置**：前面 1～7 章学完后做本章，把 isa、Runtime、Block、事件链串成完整面试答案。

## Q1：调用 `[obj method]` 完整过程？

**三大阶段**（详见 [第二章](/posts/%E7%AC%AC%E4%BA%8C%E7%AB%A0objective-c-%E5%8A%A8%E6%80%81%E8%A7%A3%E6%9E%90runtime.html)）：

**① 消息发送**
1. 编译为 `objc_msgSend`
2. nil 检查（64 位后部分合并进 msgSend）
3. isa → cache → method_list → superclass 链
4. 找到 IMP → 调用，结束

**② 动态解析**（全链未找到时）
5. `resolveInstanceMethod:` / `resolveClassMethod:`
6. 可 `class_addMethod` 补 IMP → 重新走 ①

**③ 消息转发**（resolve 返回 NO）
7. Fast：`forwardingTargetForSelector:` → 转给其他对象
8. Normal：`methodSignatureForSelector:` + `forwardInvocation:`
9. `doesNotRecognizeSelector:` → 崩溃

## Q2：KVO 原理与 isa 的关系？

> 完整原理见 [第三章 KVO](/posts/%E7%AC%AC%E4%B8%89%E7%AB%A0kvo-%E5%8E%9F%E7%90%86%E5%8A%A8%E6%80%81%E5%AD%90%E7%B1%BB--isa-swizzling.html)（§3.1 流程 / §3.2 子类重写 / §3.3 追问点）。

**一句话版**：
1. 注册时动态创建子类 `NSKVONotifying_XXX`，`object_setClass` 把 isa 指向子类（isa-swizzling）
2. 子类重写 setter：`willChangeValueForKey:` → 真实赋值 → `didChangeValueForKey:` → 回调观察者
3. 移除时 isa 改回原类
4. 注意：`isKindOfClass` 仍 YES、`isMemberOfClass` 变 NO；忘记 removeObserver 释放会崩溃

## Q3：点击按钮，从触摸到响应全链路？

1. **传递链**：`UIApplication` → `UIWindow` → … → `hitTest` 找到 `UIButton`
2. **响应链**：`touchesBegan` 发给 Button；若 Button 内部手势识别成功，可能 cancel 后续 touch
3. Button 内部 `UIControl` 触发 `sendAction:to:forEvent:` → target-action

## Q4：Category 能添加属性吗？原理？

- 不能直接加 ivar（内存布局编译期已定）
- 可以声明 property，Runtime **不会**自动生成 getter/setter
- 用 **Associated Objects** 存值，手动实现 accessor

## Q5：+load 和 +initialize 区别？

### 调用顺序总览（必背）

```
时间轴：
  dyld 加载
    → 父 +load → 子 +load → Category +load（各层按此规则）
    → main()
    → … 某刻第一次 [子类 发消息] …
    → 父 +initialize → 子 +initialize（若子类有实现）
    → 执行原本那条消息
```

| 维度 | +load | +initialize |
|------|-------|-------------|
| **谁先谁后** | **一定在 main 前**，且 **一定早于** 任意 +initialize | **懒调用**，第一次发消息前 |
| **继承链** | **父 → 子**（每层自己实现的各调一次） | **父 → 子**（子类首次消息前） |
| **Category** | 跟在该类 +load **之后**；多个 Category **链接顺序** | 无 +initialize |
| **互相影响** | +load **不会** 触发 +initialize | — |

**三种典型输出**（Animal 父类、Dog 子类，都实现了两个方法）：

```text
① App 启动加载类（main 前）：
   Animal +load  →  Dog +load  →  [Dog+XXX_category +load …]

② 第一次 [Dog alloc]（main 后，任意线程）：
   Animal +initialize  →  Dog +initialize  →  （然后才 alloc）

③ 第一次只用父类 [Animal foo]，从未用过 Dog：
   Animal +load        ← main 前仍会调（Dog 的 +load 也会调）
   Animal +initialize  ← 仅 Animal
   （Dog +initialize 不会调，直到第一次给 Dog 发消息）
```

### 对照表

| | +load | +initialize |
|--|-------|-------------|
| **本质** | Runtime **直接函数调用**（不是消息发送） | **消息发送**触发（走 `_objc_msgSend` 前的初始化钩子） |
| **调用时机** | 类 / Category **载入 Runtime 时**（`main` **之前**） | 类 **第一次收到消息** 时（**懒调用**，`main` 之后也可能） |
| **调用次数** | 每个「实现了 +load 的类/Category」各 **1 次** | 每个类 **最多 1 次** |
| **继承** | **不继承**；没写就不调 | **可继承**；子类没实现则调父类 |
| **线程** | dyld 加载线程（**不保证主线程**） | **首次发消息的那条线程** |
| **Category** | 各自 +load **都会调** | Category **没有** +initialize |
| **能否触发对方** | 调 +load **不会** 触发 +initialize | 首次消息才触发；+load 阶段类可能尚未 initialize |

### +load 调用时机（时间线）

```
App 启动
  → dyld 加载 Mach-O / 动态库
  → ObjC Runtime 注册 class、合并 Category
  → 对每个实现了 +load 的类 / Category，按顺序调用 +load   ← 这里
  → …
  → main()
  → UIApplicationMain
```

**调用顺序**（同一继承链上）：

```
父类 +load  →  子类 +load  →  该类的 Category +load（多个 Category 顺序不保证，看链接顺序）
```

```objc
@interface Animal : NSObject @end
@implementation Animal
+ (void)load { NSLog(@"Animal +load"); }
@end

@interface Dog : Animal @end
@implementation Dog
+ (void)load { NSLog(@"Dog +load"); }
@end
// 输出：Animal +load → Dog +load（与是否创建实例无关，main 前就执行）
```

**要点**：

- **类一被加载就调**，哪怕从未用过这个类
- **不能**在里面 `alloc` 别的类来「顺便初始化」并指望顺序（可能死锁 / 顺序难控）
- 适合做 **Method Swizzling**、注册监听（老 SDK）；**现在启动优化尽量别在 +load 里干重活**

### +initialize 调用时机

**第一次** 向该类 **发送任何消息** 时，Runtime 在 `objc_msgSend` 真正执行前走 **`initializeNonMetaClass`**：

```
第一次 [Dog alloc]
  → 发现 Dog 未 initialize
  → 递归：若 Animal 也未 initialize → 先初始化 Animal
  → callInitialize(Animal)  →  +[Animal initialize]   // self == Animal
  → callInitialize(Dog)     →  +[Dog initialize]      // self == Dog（若子类有实现）
  → 再执行 alloc
```

**这是 Runtime 强制顺序**，不是「消息查找碰巧先到父类」——**父类一定先于子类 initialize**（父类若已 initialize 过则跳过）。

#### 情况 A：父子 **都实现了** +initialize

```objc
// 第一次 [Dog alloc] 输出：
// Animal initialize        ← self 是 Animal
// Dog initialize           ← self 是 Dog
```

#### 情况 B：只有父类实现了 +initialize

```objc
@implementation Animal
+ (void)initialize {
    NSLog(@"initialize self=%@", self);  // 第一次 [Dog alloc] 时 self == Dog ⚠️
}
@end
// Dog 未写 +initialize
// 第一次 [Dog alloc] 只输出一次：initialize self=Dog
// Runtime 只 callInitialize(Dog)，消息 [Dog initialize] 落到父类 IMP，self 是 Dog
```

因此父类里 **必须** 写：

```objc
+ (void)initialize {
    if (self == [Animal class]) {  // 防止子类首次消息误执行父类初始化逻辑
        // 只给 Animal 自己做的一次性 setup
    }
}
```

#### 情况 C：父类已经 initialize 过

```objc
[Animal foo];   // Animal +initialize
// … 稍后 …
[Dog alloc];    // 仅 Dog +initialize，Animal 不再调
```

### Runtime 在哪里标记「已 initialize」？

**不在你的代码里**，而在 **类对象（`Class` / `objc_class`）** 的 Runtime 私有结构里：

```
objc_class (例如 Dog 这个「类对象」)
  └── class_rw_t
        └── flags   ← 用位标记状态
              ├── RW_INITIALIZING  (1<<28)  正在执行 +initialize
              └── RW_INITIALIZED   (1<<29)  +initialize 已完成
```

- 每次 `objc_msgSend` 前，Runtime 会查 **`cls->isInitialized()`**
- 若未初始化 → 走 `_class_initialize` → `initializeNonMetaClass` → 调 `+[Class initialize]`
- 开始时 **CAS 置位 `RW_INITIALIZING`**（保证只有一个线程真正初始化）
- 结束后 **置位 `RW_INITIALIZED`，清除 `RW_INITIALIZING`**
- 其他线程若同时给该类发消息，发现 `INITIALIZING` 会 **阻塞等待**（初始化期间方法缓存也会特殊处理，避免半初始化状态乱调）

```objc
// 伪代码（objc-initialize.mm 逻辑简化）
void initializeNonMetaClass(Class cls) {
    if (cls->isInitialized()) return;

    Class supercls = cls->superclass;
    if (supercls && !supercls->isInitialized()) {
        initializeNonMetaClass(supercls);   // 先父后子
    }

    // 原子抢占 INITIALIZING 位，成功者执行 +initialize
    if (成功设置 RW_INITIALIZING) {
        [cls initialize];
        cls->setInitialized();   // RW_INITIALIZED = YES
    } else {
        // 等其他线程初始化完成
    }
}
```

**和 +load 的区别**：+load **没有**这套「按类懒标记」——镜像加载阶段 Runtime **直接遍历** 已注册的类/Category 调 +load，不依赖 `RW_INITIALIZED`。

> 源码参考：Apple objc4 [`objc-initialize.mm`](https://opensource.apple.com/source/objc4/objc4-723/runtime/objc-initialize.mm.auto.html)、[`objc-runtime-new.h`](https://github.com/apple-oss-distributions/objc4/blob/main/runtime/objc-runtime-new.h) 中 `RW_INITIALIZED` / `RW_INITIALIZING`。

**Category 没有 +initialize**；Category 里的「类方法」首次使用仍走 **主类** 的 initialize 流程。

### 能手动调 +load / +initialize 吗？（高频追问）

**语法上可以**（都是普通类方法），**工程上绝对不要**。Runtime 的「只调一次」假设会被打破。

| | 手动调 `+load` | 手动调 `+initialize` |
|--|----------------|----------------------|
| **Runtime 态度** | 能执行，但 **破坏「只调一次」假设** | 能执行，但 **可能重复跑初始化逻辑** |
| **一句话** | **重复执行 + 时序错乱** | **重复执行 + 继承 self 踩坑 + 线程不可控** |

#### 手动调 `+load` 的问题

Runtime 调 `+load` 是 **直接调 IMP**（不是 `objc_msgSend`）；手动 `[MyClass load]` 走 **消息发送**，等于 **第二次执行**。

| 场景 | 后果 |
|------|------|
| **Method Swizzling** | 交换两次 = **还原**，Hook **失效** |
| **注册通知 / KVO** | **重复注册**，回调触发多次 |
| **单例 / 全局配置** | 重复初始化，状态不一致 |
| **Category 的 +load** | Runtime 已调过，手动再调也会 **再执行** |

额外风险：

- **时序错乱**：自动调在 `main` 前、固定顺序（父→子→Category）；手动调在 `main` 后任意时刻，依赖环境可能已变
- **不会触发 +initialize**：手动 `[MyClass load]` **不会** 触发 `+initialize`，若 +load 里假设类已 initialize 会行为异常
- **线程不可控**：自动调在 dyld 加载线程；手动调可能在主线程/子线程，+ 重复执行更容易出 bug

#### 手动调 `+initialize` 的问题

分两种情况：

**情况 A：类还没 initialize（第一次调）**

```objc
[Dog initialize];  // 等价于第一次给 Dog 发消息，走 initializeNonMetaClass
```

- 和 `[Dog alloc]` 触发的是 **同一条路**，**没有额外好处**
- 需要提前初始化，发 `[MyClass class]` 即可，**不要专门调 initialize**

**情况 B：类已经 initialize 过（`RW_INITIALIZED = YES`）—— 重点！**

```objc
[Dog alloc];           // 已触发 +initialize
[Dog initialize];      // ⚠️ 方法体会再跑一遍！Runtime 不拦截手动消息
```

| 场景 | 后果 |
|------|------|
| 注册 SDK / 通知 | **重复注册** |
| 改全局配置 / 单例 | **状态被覆盖或错乱** |
| 父类没写 `if (self == [Super class])` | 手动调子类时 **父类逻辑对子类再跑一遍** |

- 自动触发在 **首次发消息的那条线程**；手动调在哪个线程就在哪个线程跑，若 initialize 里改 UI 可能 **崩溃或偶现**

#### 代码题：手动调后输出什么？

```objc
@implementation Foo
+ (void)load {
    NSLog(@"load");
    method_exchangeImplementations(a, b);  // swap 一次
}
+ (void)initialize {
    NSLog(@"init");
}
@end

// main 之后：
[Foo load];        // 输出 load；Swizzling 再 swap → 还原！
[Foo alloc];       // 输出 init（首次消息，Runtime 自动触发）
[Foo initialize];  // 输出 init（再次！已 initialize 后手动调无保护）
```

#### 手动调用 · 面试 30 秒版

> **`+load` 不要手动调**：Runtime `main` 前 **直接调 IMP** 各一次，手动 `[Class load]` 会 **再执行**，Swizzling 可能失效，注册/单例 **重复初始化**。  
> **`+initialize` 不要手动调**：懒触发每个类自动 **最多一次**；类已 initialize 后手动调会 **再次执行方法体**；父类可继承，`self` 可能是子类，须 **`if (self == [Super class])`**。想提前初始化发 **`[Class class]`**。

### 易混点

| 问题 | 答案 |
|------|------|
| +load 会调父类吗？ | **会**按继承顺序依次调 **每一层自己实现的** +load，不是「继承调用」 |
| +load 会触发 +initialize 吗？ | **不会** |
| 只用子类，父类 +initialize 何时调？ | 子类 **首次消息前**，先调父类 +initialize |
| 谁更早？ | **+load 一定早于 +initialize**（+load 在 main 前，initialize 懒调用） |
| 主线程吗？ | +load / +initialize **都不要假设在主线程** |
| 能手动调 +load 吗？ | 语法可以，**不要**；Runtime 已直接调过，手动 = **确定重复** |
| 能手动调 +initialize 吗？ | 语法可以，**不要**；未 initialize 时多余；**已 initialize 后会重复执行** |
| 想提前初始化类？ | 发任意消息如 **`[MyClass class]`**，不要调 `initialize` |
| initialize 的 IMP 进 cache 吗？ | **会**（普通类方法查找）；**「已 initialize」状态** 在 `RW_INITIALIZED`，**不在 cache** |

### 面试 30 秒版

> **+load**：镜像加载、Runtime 注册后 **main 之前** 直接调用，父→子→Category，**不继承、不懒加载**；**不要手动调**，会重复执行。  
> **+initialize**：类 **第一次收消息** 时由 Runtime 触发，父→子，**可继承**，Category 无此方法；写父类 initialize 要 **`if (self == [Super class])`** 防子类误初始化；**不要手动调**，已 initialize 后会重复跑逻辑。
