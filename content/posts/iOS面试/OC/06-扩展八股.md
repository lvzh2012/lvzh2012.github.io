## 6.1 weak 原理

- `__weak` 引用登记在 **Side Table** 的 weak 哈希表
- 对象 dealloc 时遍历 weak 表，关联指针 **全部置 nil**
- 64 位 **non-pointer isa** 中 `weakly_referenced` 标志位；详见 [第一章 §1.2](/posts/%E7%AC%AC%E4%B8%80%E7%AB%A0isa-%E4%B8%8E-superclass.html)

**为何 weak 不能塞进 isa？** extra_rc 只存强引用计数，weak 表必须在 Side Table。

## 6.2 RunLoop · AutoreleasePool

> **RunLoop 源码深度内容已独立为第七章，见 [07-RunLoop源码面试题.md](/posts/%E7%AC%AC%E4%B8%83%E7%AB%A0runloop-%E6%BA%90%E7%A0%81%E9%9D%A2%E8%AF%95%E9%A2%98%E5%9F%BA%E4%BA%8E-cfrunloop.c.html)**。  
> 本章仅保留核心对照。

| 主题 | 要点 |
|------|------|
| **RunLoop** | 触摸、Timer、Source 由 RunLoop 驱动；**主线程默认开启**；子线程需 `run` |
| **AutoreleasePool** | `AutoreleasePoolPage` 双向链表；RunLoop **休眠/唤醒** 时 drain |
| **与线程** | 每条线程最多一个 RunLoop（存在线程 → RunLoop 一一对应）；主线程 RunLoop 在 `main` 里自动 run |
| **Source0 vs Source1** | Source0 应用层事件（触摸），需手动唤醒；Source1 基于 mach_port，自动唤醒 |
| **休眠原理** | `mach_msg` 系统调用进入内核态等待，零 CPU 占用 |
| **源码结构** | `__CFRunLoop` 含 `_pthread`、`_modes`、`_commonModes`、`_currentMode` 等 |
| **完整循环** | Entry → BeforeTimers → BeforeSources → Source0 → DoBlocks → BeforeWaiting → mach_msg → AfterWaiting → 处理事件 → 循环 |

## 6.4 高频面试 Q&A

### Q1：AutoreleasePool 什么时候释放？

RunLoop 每轮循环**休眠前**（BeforeWaiting）pop + push 一次；退出时最终 pop。线程退出时也 drain。或手动 `@autoreleasepool {}` 作用域结束。  
> 更多 RunLoop 源码题见 [第七章 Q&A](/posts/%E7%AC%AC%E4%B8%83%E7%AB%A0runloop-%E6%BA%90%E7%A0%81%E9%9D%A2%E8%AF%95%E9%A2%98%E5%9F%BA%E4%BA%8E-cfrunloop.c.html#79-基于源码的高频面试-qa)。

### Q2：weak 和 assign 区别？

见 [第五章 §5.2](/posts/%E7%AC%AC%E4%BA%94%E7%AB%A0oc-%E5%B1%9E%E6%80%A7%E5%85%B3%E9%94%AE%E5%AD%97@property.html)：weak 释放后 nil；assign 不置 nil。
